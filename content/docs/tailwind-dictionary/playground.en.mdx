The playground runs `tailwind-dictionary` in the browser. Change the tokens and the result and the preview update a moment later. The input tabs:

- `tokens.json` — base tokens in the [DTCG](/docs/tailwind-dictionary/dtcg) format: palette, sizes, fonts, text styles, shadows, breakpoints, animations;
- `light.json` and `dark.json` — semantic [theme](/docs/tailwind-dictionary/themes) tokens: `data-theme` switches them on any element of the page;
- `config.json` — [theme aliases](/docs/tailwind-dictionary/config) (`themeAliases`) and theme settings (`themes.default`, `themes.prefix`). The Tailwind version is switched with the button above the editor, each version has its own set of aliases. `source` and `output` are not needed: tokens come from the tabs.

## How it works

- The browser calls [`generate()`](/docs/tailwind-dictionary/api), the same code as in the CLI. Tokens and config are not sent to a server and never leave the page.
- The generator is loaded on the first build, not with the page.
- The preview is an isolated `iframe` with no network access. The Tailwind 4 result contains the `@theme` directive, which browsers do not understand, so the preview puts its variables into `:root`. A real project needs Tailwind.
- Colors in the example are written as strings (`"#2563eb"`) to make them easy to edit. The DTCG object form (`colorSpace`, `components`, `hex`) is supported too.
- If the tokens have an error, a message is shown under the editor and the result stays at the last successful one.

## What next

Copy the tokens and the config into your project and run the CLI: [quick start](/docs/tailwind-dictionary). Ready-made tokens of the same structure are in [pbstyles](/docs/pbstyles/tokens). For LESS and SCSS there is the [mixin-dictionary playground](/docs/mixin-dictionary/playground).
